## Corregido y comprobado anteriormente

- Las actualizaciones de perfil están limitadas a `display_name` en API y privilegios de base de datos.
- Las escrituras de perfil tienen limitación de frecuencia.
- Los fallos al persistir eventos de Stripe devuelven error reintentable sin exponer detalles sensibles en la respuesta.
- El proyecto usa `npm ci`, actualizaciones programadas y CI con `npm audit --audit-level=high`, cinco regresiones Node para el parser de facturas y build; el workflow de PR #33 terminó correctamente.
- La migración de seguridad de perfiles se registró aplicada en producción y la inspección de privilegios confirmó el alcance de actualización esperado.
- La migración `20261014210501_fix_payment_retention_and_subscription_state` se aplicó al proyecto Supabase `qkzmpxyefuqdhyxwfjcw`; el esquema verificado muestra `payments.subscription_status` con restricción de valores y `payments.user_id`/`stripe_session_id` nullable. El deployment público previo es el commit `515ff435a5108cb0088941ec81037a31b8ea4cce`; el end-to-end con eventos test aún no se ha completado.
- La migración `20261016130500_revoke_unsafe_public_table_privileges` se aplicó y verificó: los cuatro permisos retirados son `false` para `anon` y `authenticated` en las cinco tablas; RLS sigue activo con 10 políticas. `authenticated` conserva la actualización de `display_name` y no puede actualizar `is_admin`.
- PR #36 fusionó `@supabase/server` 1.9.2 y PostCSS 8.5.30 con lockfile actualizado; el check obligatorio pasó.
- Se prepararon páginas de detalle para Desarrollo Web, Ciberseguridad y Mantenimiento IT, con metadatos SEO, enlaces desde el catálogo y entradas en sitemap. La validación de rutas está pendiente del preview de la versión final.
- La revisión previa encontró la página principal y `/api/health` respondiendo HTTP 200; una consulta reciente de Vercel no encontró errores de ejecución durante siete días.
- La regla de protección de `main` se verificó activa: PR obligatorio, check `build` estricto, resolución de conversaciones, aplicación a administradores y bloqueo de borrado/force-push.
- En Supabase Auth están activadas la protección de cambio de contraseña y la exigencia de contraseña actual; leaked-password protection permanece desactivada por requisito del plan Pro.
